# Impulse Device — Telegram Bot для учёта продаж

## Описание

Telegram-бот для сотрудников компании Impulse Device. Позволяет менеджерам ежедневно фиксировать выручку по точкам продаж: наличные, безналичные, кредит/рассрочка, инкассация. К каждой продаже прилагаются товары с количеством и ценой. Фото чеков автоматически загружается на Яндекс.Диск. Все данные записываются в Google Sheets и локальный Excel-файл.

Администратор через бота может редактировать справочники (города, точки, менеджеры, каналы, товары).

---

## Логика работы

### 1. Регистрация продажи (`/start`)

Пользователь нажимает `/start` и проходит пошаговый сценарий из 10 шагов:

| Шаг | Действие | Тип ввода |
|-----|----------|-----------|
| 1 | Номер терминала | Текст (свободный ввод) |
| 2 | Менеджер | Кнопки (из справочника) |
| 3 | Канал продаж | Кнопки (Выставки / Санатории) |
| 4 | Город | Кнопки (из справочника) |
| 5 | Точка (название) | Кнопки (из справочника) |
| 6 | Наличные (за день) | Число |
| 7 | Безналичные (за день) | Число |
| 8 | Кредит/Рассрочка | Число |
| 9 | Инкассация | Число |
| 10 | Фото чека | Фото или пропуск |

После заполнения сумм бот сохраняет заголовок продажи и переходит к добавлению товаров.

### 2. Добавление товаров

После шага 10 бот предлагает выбрать товар из справочника, затем ввести:
- Количество
- Цена за единицу
- Комментарий (или пропустить `-`)

После каждого товара — вопрос «Добавить ещё?». После завершения — предпросмотр отчёта.

### 3. Предпросмотр и редактирование

Перед финальной отправкой бот показывает полный отчёт:
- Все данные заголовка (дата, терминал, менеджер, канал, город, точка)
- Все суммы (наличные, безналичные, кредит, инкассация, итого)
- Список товаров с суммами
- **Проверка совпадения**: если итого выручка ≠ сумма товаров — предупреждение с разницей
- Ссылка на фото чека

Пользователь может:
- ✅ Подтвердить и отправить
- ✏️ Редактировать (суммы, товары, менеджера, добавить/удалить товары, отменить запись)

### 4. Финальная отправка

После подтверждения:
- Товары дописываются в Google Sheets (вкладка «Продажи_Товары»)
- Ссылка на чек обновляется в Google Sheets
- Пользователю показывается итоговый отчёт (остаётся в чате)

### 5. Админ-панель (`/admin`)

Любой пользователь может войти в режим администратора. Режим позволяет:

| Раздел | Действия |
|--------|----------|
| 🏙️ Города | Просмотр, добавление, удаление |
| 📍 Точки | Просмотр, добавление, удаление |
| 👤 Менеджеры | Просмотр, добавление, удаление |
| 📊 Каналы | Просмотр, добавление, удаление |
| 📦 Товары | Просмотр, добавление, удаление |

- Вход: `/admin`
- Выход: `/exit`
- Удаление — через кнопки с выбором конкретного элемента
- Добавление — через текстовый ввод
- При попытке добавить дубликат — предупреждение

## Техническая часть

### Стек

- **Runtime**: Node.js
- **Telegram API**: `node-telegram-bot-api` (long polling)
- **Google Sheets**: `googleapis` (service account)
- **Excel**: `exceljs` (локальный файл sales.xlsx)
- **Яндекс.Диск**: REST API (загрузка фото чеков)
- **Процесс-менеджер**: PM2 на VPS

### Структура файлов

```
impulse-bot/
├── index.js          — точка входа, запуск бота
├── bot.js            — основная логика бота (ImpulseBot class)
├── config.js         — конфигурация из .env (не в репозитории)
├── sheets.js         — legacy wrapper на services/googleSheets.js
├── ref.js            — legacy wrapper на services/refDictionary.js
├── ref.json          — файл справочников (города, точки, каналы, менеджеры, товары)
├── yandex-disk.js    — загрузка фото на Яндекс.Диск
├── services/         — сервисы новой архитектуры
│   ├── googleSheets.js — Google Sheets + делегирование локальной записи
│   ├── dataService.js  — локальное хранение sales.json / sales.xlsx
│   ├── refDictionary.js — справочники ref.json
│   ├── yandexDisk.js   — фасад загрузки чеков на Яндекс.Диск
│   └── auth.js         — доступ открыт всем пользователям
├── adapters/         — будущие адаптеры Telegram/VK
├── core/             — SessionManager, StateMachine, MessageReplacer
├── controllers/      — будущие platform-agnostic контроллеры
├── utils/            — утилиты
├── sales.json        — локальное хранилище продаж
├── sales.xlsx        — локальный Excel с продажами и товарами
├── .env              — переменные окружения (не в репозитории)
└── README.md         — этот файл
```

### Переменные окружения (.env)

```
BOT_TOKEN=токен_telegram_бота
YANDEX_DISK_TOKEN=oauth_токен_яндекс_диска
```

### Google Sheets — структура вкладок

**Продажи_Заголовки** (A:N, 14 колонок):

| Колонка | Поле | Источник |
|---------|------|----------|
| A | Дата и время | Шаг 1 |
| B | Номер терминала | Шаг 2 |
| C | Менеджер | Шаг 3 |
| D | Канал продаж | Шаг 4 |
| E | Город | Шаг 5 |
| F | Точка (название) | Шаг 6 |
| G | Наличные (за день) | Шаг 7 |
| H | Безналичные (за день) | Шаг 8 |
| I | Кредит/Рассрочка | Шаг 9 |
| J | Инкассация | Шаг 10 |
| K | Итого выручка | Расчёт (G+H+I+J) |
| L | Фото чека | Ссылка на Яндекс.Диск |
| M | Комментарий | Из товаров |
| N | ID транзакции | UUID |

**Продажи_Товары** (A:G, 7 колонок):

| Колонка | Поле |
|---------|------|
| A | ID записи |
| B | ID транзакции (связь с заголовком) |
| C | Название товара |
| D | Количество |
| E | Цена за единицу |
| F | Сумма позиции |
| G | Комментарий |

### Справочники (ref.json)

Хранятся в файле `ref.json` и редактируются через `/admin`:

```json
{
  "cities": ["Москва", "Сочи", "СПб", ...],
  "terminals": ["Ессентуки Русь", "Ессентуки Юность", ...],
  "channels": ["Выставки", "Санатории"],
  "managers": ["Седова И.", "Гусарова К.", ...],
  "products": ["Kegel", "Neuro", "Sport", ...]
}
```

### Механизм затирания сообщений

Все промежуточные сообщения бота удаляются перед отправкой нового (`sendAndReplace`). В чате остаются только:
- Текущее актуальное сообщение (с кнопками или запросом ввода)
- Предпросмотр отчёта
- Финальный отчёт об отправке

### Доступ

Whitelist не используется. Команды `/start` и `/admin` доступны всем пользователям.
